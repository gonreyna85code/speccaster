# petstore-ci — a complete SpecCaster example

A tiny pets API with an OpenAPI spec, a **committed** SpecCaster-generated
suite, and a CI workflow. Everything here runs with zero external services.

```
server.js                       the API (node:http, no deps)
openapi.yaml                    the contract the API must match
speccaster/contract.test.js     generated by: npx speccaster init (then hand-editable)
.github/workflows/speccaster.yml auto-generated drift gate + test run
```

## Run it locally

```bash
npm start                                  # starts the API on PORT or :8080
# in another terminal:
SPECCASTER_BASE_URL=http://localhost:8080/v1 npm test     # runs the committed suite
npx speccaster test --spec openapi.yaml    # same thing, via the CLI
npx speccaster drift --spec openapi.yaml   # CI gate: fails if suite and spec disagree
```

## The loop this demonstrates

1. `speccaster init` writes `speccaster/contract.test.js` + the workflow.
2. On every push/PR the workflow regenerates the suite from the spec and runs
   `drift` — if the committed suite is out of date, **the build fails**.
3. The suite runs against your API at `${{ secrets.SPECCASTER_BASE_URL }}`.

Change `openapi.yaml` (say, rename `GET /pets` → `GET /animals`) without
committing a regenerated suite, and watch `drift` catch it.

## CI failure demo

```bash
node -e "fs=require('fs');let d=fs.readFileSync('openapi.yaml','utf8');fs.writeFileSync('openapi.yaml',d.replace('#/paths/pets','#/paths/animals'))"
npx speccaster drift --spec openapi.yaml    # exit code 1
```
